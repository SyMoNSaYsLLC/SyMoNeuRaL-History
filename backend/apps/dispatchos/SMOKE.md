## The bug this run found, which 37 unit tests could not

`POST /ask` hung past a 30-second client timeout and blocked the API for every other caller.
The route was `async def` and called `ai.ask` directly; the injected callable is
`guide_ask_model`, which does `run_coroutine_threadsafe(...).result(timeout=45)` — it
schedules work on the event loop and blocks waiting for it, so calling it from inside the loop
deadlocks the loop with the call that needs it. Fixed with `await asyncio.to_thread(...)`,
which is exactly why guide calls it from a worker thread.

Every unit test injected a plain synchronous stub, and such a stub is perfectly happy on a
blocked loop. **Only the live run could find this.**

## The other bug, found the same way

The first `status()` returned `"sub": "transport dispatch"`. `Unit.sub` is
`list[SubUnit] | None`, so pydantic raised inside `build_status()` — which the rack websocket
and every visitor's status poll call. `/api/status` returned 500 site-wide until it was fixed.
The surface was healthy; the rack ROW broke the page. There is now a test that constructs the
real `api.Unit` in both switch positions, verified by re-introducing the exact bug.
