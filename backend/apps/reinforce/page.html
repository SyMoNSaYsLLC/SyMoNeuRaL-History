SyMoNeuRaL Reinforce

A training bay, not a status panel. Pick a base model that is genuinely on this box, pick a predetermined tuning method, and see what the run will cost before it starts. The technique is 4-bit low-rank adaptation: the base weights are quantised to four bits and frozen, and only a small adapter is trained. That is what makes a 7B model trainable on one 15.92 GiB card at all — full fine-tuning of the same model would need roughly eight times this card.

This surface is off. It accepts work only when the operator switches it on, because a training run takes the whole GPU and is never evicted to serve a page — an open one would take chat, image and remix offline for a single request.

Configure

There is no default dataset and no fallback. SyMoNeuRaL's own training corpus is a protected artefact: it is never listed, previewed, counted or read by this surface, and naming its path here is refused rather than accepted. Nothing this page returns — including an error message — contains a line of dataset content.

This run takes the whole rack

A fine-tune holds the GPU until it finishes or is stopped deliberately. Chat, image and remix queue behind it for its entire duration, and the governor will not evict a training run to serve a page view. That is architectural, not a limitation waiting to be engineered away — one card, and the weight sets do not co-fit.

What one 16 GiB card cannot do

Published for the same reason the PCIe Gen 3 ×8 ceiling and the failed multi-stream overlap are published: a negative result measured here is worth more than a positive one taken from somebody's marketing.

  • No full fine-tuning, of anything. Weights, gradients and two optimiser moments for a 7.6B model come to roughly 113 GiB — about eight times the budget. projected
  • No 14B at all — and this reverses an earlier estimate. A 14B was projected here as feasible at rank 16 and sequence 1024. Then a real run on the 7B measured its peak and found the projection 2.03 GiB light, because the parameters that are not quantised — the embeddings and the output head — are converted to full precision before training, at four bytes each rather than two. On a model with a 152,064-token vocabulary and an untied output head that is 1.56 billion parameters, or 5.8 GiB of the budget before a single activation exists. The corrected arithmetic puts every 14B configuration over the limit, so the preset table refuses all of them and shows the sum. measured on the 7B, projected onto the 14B.
  • Lowering the rank does not rescue a model that is too large. Rank governs the adapter, and the adapter is a fraction of a gibibyte of an eleven gibibyte problem. The only rungs that help are a shorter sequence and a smaller base, and the panel says which one it is offering. projected
  • No training while serving. One card, serialised. A run locks chat, image and remix out for its whole duration.
  • No multi-GPU anything, and CPU offload is not a rescue. One card, no NVLink, and this host is capped at PCIe Gen 3 ×8 — offloading optimiser state across that link every step converts a memory problem into a wall-clock one. measured
  • Nothing trained here is served automatically. A finished run produces adapter weights in the training format; the chat surface loads a different one. A page that said "trained" while chat still ran the previous adapter would be a dishonest status, so promotion stays a deliberate, manual step.
