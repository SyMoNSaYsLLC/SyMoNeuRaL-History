    Tuner does not use the GPU. This is the card the rest of the stack shares, shown here so you can see what it is doing; nothing on this page waits for it.

    Where your credentials go

    Nowhere. They stay in this browser’s localStorage and travel with each request. The server holds them only for the life of a stream and keeps them out of process arguments and error text. Nothing is written to disk.

    Favourites too. The star beside a channel writes to this browser and nothing else. There is no account here and no list of what you watch on this box.

    Why there is no “Trending”

    A playlist is a list of names and URLs. It carries no view counts, no ratings and no trend feed, so a tab called Trending would be a number this machine cannot read — the same dishonest pixel as a status light that is green because green looks better.

    Most carried is what the data does support: it counts how many of your provider’s own groups carry the same title, and how many listings of it exist — a channel duplicated across Sports, Premium and 4K is genuinely more prominent in that lineup. Ties fall back to the order the provider wrote the playlist in. Every row prints the counts it was ranked by, so you can check it.

    How the stream is handled

    ffmpeg copies the stream rather than re-encoding it, so it costs muxing and network rather than compute — this surface never queues behind the GPU. The upstream socket is opened in Python against a pinned, validated address and the bytes are piped in; ffmpeg is never handed a URL, so it cannot make its own DNS lookup or follow its own redirect.

    Playback is hls.js (Apache-2.0, vendored at /hls.js), because Chrome and Firefox will not play an .m3u8 natively.

    What the model actually does here

    Your filter runs before the model does. Matching your words against the list already in this browser is pure JavaScript over an array — it is done in single-digit milliseconds and the page prints the measurement. Results appear first; the card is only asked afterwards, and only when the local pass came back thin or left one of your words unmatched.

    When it is asked, it reads your question, not your playlist. The prompt comes back as one line of keywords, which widen the match already on screen. Feeding thousands of channel names through a 7B would be slow, would hold the GPU lock while it ran, and would be worse at it than a substring match. The pill above the results says which of those happened: not needed, answered, added nothing, or unavailable.

    Known gaps, stated rather than hidden

    The vendored hls.js is the light build: no subtitle or alternate-audio rendering. The Xtream client has never been tested against a live panel beyond channel listing. Series episodes list without URLs rather than with guessed ones, and AES-encrypted HLS is refused rather than decrypted.

    This is a 16 GB consumer card, and it is a test bench

    Chat and image never run at the same time here. A lock hands the GPU to exactly one surface and the other waits, because both weight sets do not fit in 15.92 GiB at once — and when they swap, we wait for the driver to actually hand the memory back before the next one starts. If you are queued behind someone, that is not a bug; it is one card doing one thing at a time.

    RavenCalc is the exception — it is SymPy on the CPU, so it never touches the GPU and never queues. Everything here is a demonstration of the stack on the smallest machine we would ever ship, not a statement of capacity. A server we spec for you would not be sharing one GPU with itself.
