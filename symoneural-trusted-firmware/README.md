# symoneural-trusted-firmware

A reproducible, verifiable, rollback-safe GPU foundation for SyMoNeuRaL.

**Scaffold gate.** `inventory` and `verify` are real and read-only. `stage`,
`test`, `promote` and `rollback` refuse to act and print the plan they *would*
run. Nothing here installs, loads, unloads, signs or replaces anything — no
`modprobe`, no `rmmod`, no dkms build, no initramfs write, no bootloader touch,
no package manager call.

## Trust model

```
   CANDIDATE ──verify+test──▶ (human decision) ──▶ PRIMARY
                                                     │
   RECOVERY ◀────────────── copy of prior PRIMARY ────┘
        └──rollback──▶ PRIMARY
```

| slot | meaning |
|---|---|
| **PRIMARY** | the currently trusted operational stack |
| **CANDIDATE** | a new source/build/runtime combination under validation |
| **RECOVERY** | known-good rollback target |

**Nothing promotes itself.** `promote` requires `verify(CANDIDATE) == TRUSTED`,
all execution checks passing, and an explicit human confirmation token. That is
enforced by refusing to act, not by a flag someone can flip.

## The coupling rule that motivates this

NVIDIA ships the **kernel modules, the GSP firmware blob and the userspace
driver as one release**. A partial upgrade — new modules against an old GSP
blob, or a userspace `libcuda` from a different release — is not a supported
configuration and can fail in ways that look like application bugs. That is
what `RELEASE_TRIPLE_COHERENT` exists to catch, and it is the single check most
likely to fire during a real upgrade.

## Naming hazard

`nvidia_kmd` in this manifest means **NVIDIA open kernel modules**. It has
nothing to do with the Hugging Face **`kernels`** pip package, which is a
userspace library of fused model ops (and is, separately, the thing currently
blocking the GPT-OSS MXFP4 player). Userspace runtimes are recorded under
`higher_level_runtimes` and are **never a trust root**.

## Components tracked

1. Linux kernel · 2. NVIDIA open kernel modules (+ per-module sha256) ·
3. GSP firmware (+ blob sha256) · 4. NVIDIA userspace driver (+ libcuda sha256) ·
5. CUDA userspace/runtime · 6. GPU PCI identity + UUID + VBIOS ·
7. compute capability / SM arch · 8. Secure Boot + kernel lockdown ·
9. PyTorch CUDA runtime identity · 10. optional Triton

## Usage

```bash
tools/tfctl.py inventory --json              # read the live stack
tools/tfctl.py inventory --emit-manifest PRIMARY
tools/tfctl.py verify --slot PRIMARY         # TRUSTED / MISMATCH / UNKNOWN
tools/tfctl.py stage|test|promote|rollback   # refuse; print the plan
```

`verify` deliberately **does not import torch** — a trust check must not itself
create a CUDA context. Torch identity is collected separately by
`inventory --with-torch`, and the execution checks live under `test`.

## Checks

**Implemented (read-only):** `KMD_VERSION_MATCH`, `GSP_VERSION_MATCH`,
`USERSPACE_VERSION_MATCH`, `CUDA_VERSION_MATCH`, `KERNEL_RELEASE_MATCH`,
`GPU_ID_MATCH`, `GPU_PCI_MATCH`, `VBIOS_MATCH`, `SM_CAPABILITY_MATCH`,
`UPSTREAM_COMMIT_MATCH`, `MODULE_HASH_MATCH`, `GSP_BLOB_HASH_MATCH`,
`RELEASE_TRIPLE_COHERENT`.

**Declared but not implemented:** `MODULE_SIGNATURE_MATCH`,
`SM120_EXECUTION_PASS`, `CUDA_SAMPLE_PASS`, `PYTORCH_SM120_PASS`.

Unimplemented checks report `UNKNOWN` and **drag the overall verdict to
`UNKNOWN`**. They are never silently skipped, and a slot with 13 green checks
and 4 unknowns does not read as `TRUSTED`. That is deliberate: this file exists
because a figure with no provenance beside it is the thing this project distrusts
most.

## Secrets

The manifest stores version identity and **public** file hashes only. No private
signing keys, no certificates, no tokens. `MODULE_SIGNATURE_MATCH`, when
implemented, must verify against the public key in the kernel keyring and must
not copy key material into the manifest.

## Integration with the GPU governor

```
trusted firmware verify == TRUSTED
        ↓
GPU governor production-enabled
        ↓
Qwen / GPT-OSS / image players
```

A failed trust check **blocks automatic promotion to production**. It must not
block developer diagnostics — an operator debugging a broken stack needs the
players to start, and a trust gate that prevents its own diagnosis is worse than
none.

## Files

| path | role |
|---|---|
| `manifest/trusted-stack.json` | measured slots (PRIMARY / CANDIDATE / RECOVERY) |
| `manifest/trusted-stack.schema.json` | JSON Schema for the manifest |
| `tools/tfctl.py` | inventory / verify / stage / test / promote / rollback |

The manifest is **generated by measurement** (`inventory --emit-manifest`), never
hand-written — a transcribed hash proves nothing.
